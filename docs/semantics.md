# 三形态语义边界（必读）

> 形态切换切换的是**部署与传输形态**，不自动等价**业务语义**。本页列出已知的语义差异；
> 把切换当作"不经验证的灾备按钮"之前，请逐条对照。

## 事务

- **mono**：本地调用即同线程方法调用。若各服务共用一个事务管理器/数据源，跨"服务"调用可加入同一事务（传播生效）。
- **micro（两种传输同）**：跨服务调用是远程调用，**不传播事务**。需要最终一致性时用补偿/消息/outbox，不要假设回滚会跨进程。

## 对象引用与副作用

- mono 下传参传的是**对象引用**（可变对象、同一实例的后续修改可见）。
- micro 下传参经 JSON 序列化（深拷贝、丢失 transient/自引用/自定义等价语义）。**契约 DTO 应当是纯数据**，不要依赖引用语义或不可序列化字段。

## 超时与失败

- mono 调用没有网络超时/重试概念；micro 有（Dubbo timeout / HTTP connect+read 超时，重试均为 0——写操作不被重复执行）。
- 失败隔离：micro 下提供方崩溃消费方收到超时/连接错误；mono 下提供方异常直接以调用栈抛出。错误处理代码需同时容忍两类。

## 定时任务与调度

- 同一份代码在 mono 下只有一个进程实例；micro 下每个服务一个进程。**@Scheduled/消息消费者在两种形态下的执行次数不同**——多实例场景需要分片或选主，切形态前确认。

## 会话与上下文

- IamContext 透传在三种形态下语义一致（mono 同线程 ThreadLocal；micro 经 attachment/header）。
- 会话本体在 Redis（宿主环境事实）。切形态不换会话存储，登录态不丢；但**上下文里携带的权限快照是否最新**取决于宿主的会话刷新策略，与形态无关。

## 结论

- 交付/演示/资源受限场景：直接切，差异基本无感。
- 生产形态变更（微服务↔单体）：**先跑三形态回归**（本项目 scripts/smoke.py 的两形态一致性断言就是为此设计），重点覆盖事务边界与定时任务。
